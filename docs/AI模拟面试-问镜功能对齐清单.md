# 面试蛙 AI 模拟面试：问镜功能对齐清单

日期：2026-10-12。

## 交付约定

用户明确要求“要和问镜一样”。以问镜的模拟面试功能和用户操作流程为验收基准，不再以“参考部分交互”或简化 MVP 作为最终交付。保留面试蛙品牌、主题、登录体系和已有基础设施。本文是修正后的开发与验收约定，尚未实现的能力不得在页面或验收记录中表述为已完成。

源码基准：https://github.com/liuhan-agent/Agentic_Interviewer ，提交 `0c64377b7758d3bf12ac51073d9b92246f1dc669`。当前依据是源码核查；尚未运行上游完整服务，运行体验一致性仍需逐项验证。

## 功能矩阵

| 模块 | 应交付行为 | 改造起点（旧简化版） | 验收依据 |
| --- | --- | --- | --- |
| 方向设置 | 与上游方向及分组对照，方向影响考察维度和选题 | 目前题库选择代替方向选择 | 不同方向形成不同考察配置；题库是知识来源，不能冒充方向 |
| 候选人设置 | 上传或粘贴简历，解析画像、技能、项目、关注点；可预览和编辑 | 仅背景文本 | 解析失败可重试或修正；编辑结果真正用于后续面试 |
| 岗位设置 | 岗位、级别、JD 解析、技能与考察维度、短/标准/深度选择 | 仅文本和题目数量 | JD 解析结果可确认；级别、深度改变面试计划 |
| 自我介绍 | 开场提问，回答后补充候选人画像，再进入技术考察 | 直接出题 | 自我介绍独立处理，不套技术题参考答案评分 |
| 面试导演 | 每轮结合画像、岗位、已考察内容和回答决定下一步 | 固定题目顺序 | 可追溯为何选择此题、为何追问或结束；避免重复考察 |
| 项目深挖 | 关联简历项目、职责及技术决策，房间展示关联内容 | 无项目画像与关联 | 问题围绕实际候选人项目，不凭空编造项目经历 |
| 知识检索 | 复用问镜检索决策的能力，由 ES 提供全文与向量召回 | 正式面试未使用已建检索层，无真实 Embedding | 检索进入正式选题链路，记录来源；Embedding 配置与质量独立验收 |
| 动态追问 | 依据回答缺口和策略调整，支持多轮追问及深度预算 | 每道题最多一次 | 追问针对缺口，次数、总轮次和调用预算生效 |
| 评分合同 | 出题时冻结评分依据、必答点和最低要求 | 参考答案三维评分 | 评分依据版本固定，不能评分时临时改变标准 |
| 评价验证 | 评价后验证证据、覆盖情况和评分一致性 | 单模型直接评分 | 引用能定位到用户回答；无依据结论被拒绝或修正 |
| 房间交互 | 对齐上游自我介绍、当前题、关联项目、提示、回答、跳过、重试、结束和状态展示 | 部分按钮存在，缺提示及阶段信息 | 按钮执行真实后端能力；刷新不丢失状态；提示记录用于评价上下文 |
| 报告 | 完整维度分析、回答证据、优缺点和面试结论；独立报告页面 | 简单平均与建议去重 | 报告可追溯到轮次，未覆盖维度不伪造评分 |
| 训练计划 | 根据报告生成具体、可执行的训练任务 | 无独立训练计划 | 每项建议关联薄弱点及面试证据 |
| 历史与回放 | 会话历史、轮次回放、报告查看和继续面试 | 已有基础历史 | 用户隔离、跨刷新和服务重启可恢复，旧数据可查看 |
| 策略学习与经验 | 核查并适配上游 reward_update、experience_extractor 的实际行为 | 未实现 | 明确学习输入、写入及关闭语义，不能用空节点冒充 |

## 基础设施适配

- 浏览器 → Java 登录鉴权 → Nacos/OpenFeign → Python/FastAPI。
- LangGraph 编排，MySQL 保存会话、命令、检查点及策略数据。
- ES 使用独立 AI 索引提供 BM25 与向量检索；不能为保持上游实现细节而默认引入 PostgreSQL、pgvector 或 Chroma。
- Next.js / Ant Design 保留面试蛙主题，重建与上游功能对应的组件和操作流程。
- 新增代码提供中文注释。移植上游代码及提示词时保留许可与版权声明，记录版本和适配内容。

## 实施顺序与发布门槛

第一批实际代码与验收状态见 [第一批实现与验收](AI面试问镜对齐-第一批实现与验收.md)，不将下表的旧版基线当成当前运行状态。

详细接口、数据、状态和验收要求见 [问镜功能对齐开发规格 v0.2](AI模拟面试-问镜功能对齐开发规格-v0.2.md)。该规格取代原 MVP 的最终交付标准；当前代码仍是简化版。

1. 建立上游页面与接口基线、版本化数据契约；接入方向、简历异步解析及编辑、JD 解析和深度设置。
2. 接入自我介绍、画像更新、基础导演、题目来源适配与出题时冻结的评分合同。
3. 接入评价、验证、上下文治理，再接入依赖评价缺口的多轮追问、项目深挖、提示及完整 ES 检索。
4. 对齐维度聚合、完整报告、独立报告页面、训练计划、历史回放、设置快照、删除与用户反馈。
5. 对齐策略更新、经验提取及聚合；补齐上游其他能力映射，完成逐项真实验收。

每阶段是实现顺序，不是授权删减功能。逐项记录“已实现 / 未实现 / 验收失败 / 需额外配置”。基础链路通过或按钮出现不等于功能对齐通过。

问镜其他账号运营、BYOK、语音及管理能力需纳入后续上游全量功能盘点，不能默认为已经完成或悄悄排除；与现有登录、管理员功能重叠的能力应复用，并记录对应关系。涉及外部语音或 Embedding 服务时说明实际配置缺口，不以模拟输出代替。

补充遗漏：异步简历解析任务及进度、默认岗位模板、等待提示、面试设置快照、会话删除、用户反馈、诊断轨迹均进入功能映射与验收，不用“房间交互”一个概括词代替。
