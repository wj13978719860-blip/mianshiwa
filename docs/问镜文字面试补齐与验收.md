### 3. 复用 Redis 缓存与限流

运行配置写在被 Git 忽略的 `.runtime/ai-service.env`；无真实密钥的模板在 AI 服务 `.env.example`。

```dotenv
REDIS_URL=redis://127.0.0.1:6380/1
RESUME_PARSE_CACHE_BACKEND=redis
RESUME_PARSE_CACHE_REDIS_PREFIX=mianshiwa:ai:resume_parse
RATE_LIMIT_BACKEND=redis
RATE_LIMIT_REDIS_PREFIX=mianshiwa:ai:rate_limit
```

使用 Docker Redis 的 6380 端口和独立 DB/键前缀。新增 Redis 客户端依赖并更新依赖锁文件。锁文件同时补齐了此前已经声明的问镜依赖；本机没有在运行中强制同步、升级全部依赖。

- Redis 跨进程窗口改用墙钟时间，内存限流保留单调时间。
- 连接超时 1 秒、读写超时 2 秒，避免缓存故障无限阻塞。
- 启动检查 Redis；共享限流故障返回可重试的 503、`Retry-After: 3`，不暴露连接信息。
- 简历解析缓存保留上游故障降级行为；缓存不保存原文预览。

真实验证：两个独立限流客户端共享同一窗口；简历经 Java 网关重复上传，第二次解析返回 `cached=true`。只清理本次测试键，没有执行 Redis 全库清空。

### 4. 按用户隔离草稿和本地历史

新增前端 `userStorage.ts`，使用 Java 当前登录用户 ID 构造 `mianshiwa:interview:user:<id>:` 前缀，覆盖设置草稿、简历编辑缓存、历史快照、会话恢复凭证。

退出或切换账号时清理上一账号的本地材料，并重挂面试页面，避免旧内存状态留给新账号。未登录、SSR 或浏览器禁用存储时不读写材料。

**兼容影响：旧版没有归属的浏览器草稿会清理。**旧历史的 `ownerUserId` 是 Python 影子用户 ID，不能据此冒认为 Java 用户。服务端历史不会删除，会重新加载。其他业务缓存不会清空。

### 5. 修复回答重试与面试收尾

前端原幂等键带冒号，上游校验器不接受，导致相同回答重试返回 409。现在用合法的 `answer-<turn>-<hash>`，相同回答使用相同键，改写回答使用新键。保留上游校验规则。

真实跳题验收发现两个问题，均已修复：

- 跳题只进入 LangGraph 状态，未写事实表，回放少一题。现在持久化原题干、空答案、空分数；自我介绍不占正式第 0 轮。
- 经验提取对空分数执行 `float(None)`，会在报告收尾阶段崩溃。现在排除跳题、无评分、非有限分数和模型降级结果，避免当 0 分学习。

### 6. 修复模型 JSON 截断

最初两场验收虽然生成报告，但训练计划的 2048 token 预算耗尽，产生不完整 JSON，实际来源是 fallback。没有把这两份旧报告冒充完整模型结果。

新增 `COACH_LLM_MAX_TOKENS`，本机 Coach 和 Evaluator 分别配置 8192 token。训练计划有独立预算，其他节点没有统一提高。兼容协议返回 `finish_reason=length` 时明确判定截断，不再把残缺正文记录为成功；Coach 降级原因标记 `output_truncated`。

调整后用原 3 轮、8 轮检查点分别重新调用 Coach，均返回 `source=llm`、完整 JSON 和 4/5 项练习任务。这是独立验证，没有覆盖已有历史报告。之后新开的重启/跳题验收会话，完整流程生成的报告也是 `source=llm`。

### 7. 恢复前端构建检查

Axios 拦截器实际返回业务正文，旧类型仍认为返回 `AxiosResponse`。修正公共请求类型、FormData 边界处理和 SSR 登录跳转，补齐相关页面的 unknown 异常处理、动态路由参数与列表类型。没有靠忽略 TypeScript 错误通过构建。

`NEXT_BUILD_DIR` 可以将验证产物放进 `.next-build-check`，避免污染运行中的 `.next`。前端仍运行开发模式。
