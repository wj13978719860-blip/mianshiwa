# 面试蛙独立 AI 服务 MVP Spec

版本：v0.2 修订稿

日期：2026-10-12
状态：已完成本机通信 MVP 实施与验收，见 [实施与验收记录](AI服务MVP实施与验收.md)；本文件为需求基准，真实模型与面试功能仍不在本版本范围内。

修订记录：v0.2 取代 v0.1，分离业务就绪与注册状态，明确停用与版本回退，指定 Sa-Token 权限机制，补齐请求契约、故障验收时限及依赖验证前置条件。

## 1. 目标与技术决定

本次交付独立 Python 服务与现有 Java 后端的最小通信闭环：两个服务注册现有 Nacos，Java 通过 OpenFeign 按服务名调用 Python 测试接口，停机时错误可控，重启后恢复。

已确定的方向：

- 原业务后端继续使用 JDK 8 / Spring Boot 2.7.2。
- AI 服务采用 Python 3.11、FastAPI；后续使用 LangGraph 编排面试。
- 参考问镜的面试状态机、评分证据、上下文治理和执行轨迹设计。
- 注册中心复用现有 Nacos，Java 调用使用 OpenFeign + Spring Cloud LoadBalancer。
- 本版本不引入 Spring AI，也不升级原后端 JDK。
- 品牌为“面试蛙”，保留内部 `mianshiya` 技术标识。

## 3. 范围

### 3.1 本次必须交付

1. 新增 `mianshiya-ai-service/`，独立依赖、配置、启动说明。
2. Python 服务注册、心跳/连接维护、重连与正常退出注销。
3. Java 后端注册发现，兼容现有 Nacos 配置中心。
4. Java Feign 客户端按服务名调用 Python，配置超时，禁止自动重试。
5. 健康检查、服务凭证、请求标识及基础脱敏日志。
6. 管理员验证入口和不依赖模型的固定测试响应。
7. 启动脚本、可重复的验收步骤、回退说明。

### 3.2 本次不包含

真实模型调用、题库同步、Embedding、ES 向量索引、RAG、LangGraph 面试流程、动态追问、回答评价、能力档案、SSE 和前端改版。

无需模型 API Key 即可验收本版本。原有 AI 功能保持原调用路径，不自动迁移到新服务。

## 4. 架构与职责

```text
Next.js → Java 业务后端（8101）
                │ OpenFeign + LoadBalancer，按服务名调用
                ↓
          Python / FastAPI（8102）

Java 与 Python → 同一 Nacos namespace / group
```

| 服务 | 职责 |
|---|---|
| Java | 用户身份与权限、公开 API、业务状态和持久化、发起内部调用 |
| Python | 内部 AI 能力接口；本版本仅提供探测响应 |
| Nacos | 注册实例并供调用方发现，不转发 HTTP 业务流量 |

双方都注册到 Nacos；本版本只实现 Java 调用 Python，不新增反向调用接口。Python 本版本不连接 MySQL、Redis 或 ES。

## 5. 服务发现与生命周期

| 配置 | 本地默认值 |
|---|---|
| Java 服务名 | `mianshiya-next-backend` |
| Python 服务名 | `mianshiya-ai-service` |
| Python 端口 | 8102，实施前检查占用 |
| Nacos 地址 | `127.0.0.1:8848` |
| namespace | public，外部配置使用空 ID；Python SDK 2.0.11 的 gRPC 参数规范化为 `public`，自定义 namespace 使用真实 ID |
| group | `DEFAULT_GROUP` |
| 注册地址 | 两个服务运行于同一主机时为 `127.0.0.1` |

注册实际可访问的监听地址，不能把 `0.0.0.0` 当作实例地址。容器或跨主机部署时必须单独配置可达地址，不能沿用回环地址。

Java 以 Spring Cloud 2021.0.x 及匹配的 Alibaba 集成组合作为候选，必须先验证与 Boot 2.7.2 / JDK 8、现有配置中心和 Sentinel 的兼容性，再锁定补丁版本与 BOM。候选版本族不等于已经验证通过。

Python 优先选择官方维护、兼容 Nacos 2.4.3 的 Python SDK；具体版本在实现前验证后锁定。使用临时实例，依照 SDK 协议维护心跳或 gRPC 连接，不重复实现另一套心跳循环。

Python 生命周期：

1. 启动时校验配置，缺少内部凭证则启动失败。
2. FastAPI lifespan 初始化 Nacos 客户端并注册，避免模块导入时执行注册。
3. 从 lifespan 开始初始化 Nacos 客户端起，30 秒内完成首次注册，否则中止启动。该预算包含 SDK 初始化、连接、请求与退避，不能仅限制外层重试次数；清理客户端后进程最迟在该时点后 5 秒内以非零状态退出。
4. 首次初始化成功后，Nacos 断开只更新注册状态；业务仍可用时就绪检查仍返回 200，探测接口仍接受缓存实例发来的合法请求。客户端有界退避重连，不进行忙循环。
5. 重连后重新建立注册状态。业务就绪与注册状态分别维护，不把连接恢复直接当作注册成功，也不把注册断开直接当作业务故障。
6. 正常退出先进入停止状态、拒绝新业务请求，再尝试注销并关闭客户端；退出清理总预算为 5 秒，失败时记录脱敏日志并结束退出。
7. 异常退出依赖 Nacos 临时实例失效机制；Java 同时处理缓存实例连接失败。

MVP 使用单 Uvicorn worker，验收启动禁用 `--reload`，避免重复注册。多 worker 与容器部署另行设计。

## 6. 接口契约

### 6.1 Python 健康接口

| 接口 | 行为 |
|---|---|
| `GET /health/live` | 进程可响应返回 HTTP 200；不调用模型或 Nacos 远程接口 |
| `GET /health/ready` | 首次初始化及注册已完成、业务可接收请求且未进入停止状态时返回 200，否则 503；运行中仅 Nacos 断开不改变业务就绪 |

响应只返回必要状态，不暴露凭证、私有地址或完整配置。就绪响应包含独立字段，例如 `{"status":"ready","registry":"disconnected"}`。`registry` 可为 `registered`、`disconnected`、`unknown`；不能确认时使用 `unknown`，不得伪报注册成功。通过 SDK 可用事件及必要的有界后台检查更新，健康 HTTP 请求本身不远程查询 Nacos。Nacos 不会自动根据此健康接口更新实例状态，实例健康仍按所选注册协议维护。

### 6.2 Python 内部探测接口

`POST /internal/v1/probe`

请求头：

```http
X-AI-Service-Token: <由本地私有配置提供>
X-Request-Id: <Java 生成的 UUID>
Content-Type: application/json
```

请求体：

```json
{"message": "hello"}
```

`message` 必须是字符串，不能为空或全空白；原始字符串最多 256 个 Unicode 码点，Java 与 Python 按同一规则校验，不允许类型自动转换。未知字段拒绝。响应 HTTP 200：

```json
{
  "requestId": "同请求头 UUID",
  "service": "mianshiya-ai-service",
  "version": "0.1.0",
  "mode": "stub",
  "reply": "AI service is reachable"
}
```

此接口明确为探测桩，不声称已经调用模型。使用 Pydantic 校验请求和响应契约。

| 情况 | Python HTTP 状态 | 内部错误标识 |
|---|---|---|
| 凭证缺失或错误 | 401 | `UNAUTHORIZED` |
| 请求格式或字段错误 | 422 | `INVALID_REQUEST` |
| 服务未就绪 | 503 | `SERVICE_NOT_READY` |
| 未预期异常 | 500 | `INTERNAL_ERROR` |

统一错误体包含 `requestId`、`error`、脱敏 `message`；配置异常不能回显凭证。内部凭证使用安全比较，认证先于业务处理。

请求标识规则：

- Java 在验证入口的请求处理最前面生成 UUID，不信任外部传入值；成功、权限失败、参数失败和远程失败响应都附带 `X-Request-Id`，日志使用同一个标识。
- Python 接受标准带连字符的 UUID 并规范化为小写；缺失或非法时生成替代 UUID 供错误追踪，在凭证有效时返回 422 `INVALID_REQUEST`，不执行探测逻辑。
- Python 对有效凭证先做请求标识和请求体验证；凭证无效优先返回 401。所有应用生成的内部探测响应都附带 `X-Request-Id`，响应体中的 `requestId` 与该头一致。
- Java 校验成功响应的必需字段与 `requestId`；结构不符合契约或标识不匹配，按内部协议错误处理，不返回成功。

### 6.3 Java 管理员验证入口

`POST /api/ai/service/probe`

明确使用现有有效机制 `@SaCheckRole(UserConstant.ADMIN_ROLE)`，并验证登录校验及角色解析生效。禁止使用旧 `@AuthCheck` 作为该入口的保护机制：当前 `AuthInterceptor` 的 `@Aspect`、`@Component` 已注释。游客返回现有未登录码 40100，已登录普通用户返回无权限码 40101，两者均不得调用 Python。

客户端不能指定目标 URL、内部凭证或服务名。请求体与内部探测一致；Java 在远程调用前校验，非法 JSON、空请求体、字段缺失、类型错误、未知字段、全空白和超长输入返回现有 `PARAMS_ERROR`（40000），`data=null`，不调用 Python。异常映射限定在新增入口，避免改动现有接口行为。Feign 拦截器仅对 AI 客户端添加服务凭证和请求标识，不透传用户 Cookie。

成功沿用 `BaseResponse`：`code=0`，`data` 为 Python 探测结果。远程连接、超时、认证、协议及服务端错误映射为现有 `OPERATION_ERROR`（50001），`data=null`；日志区分具体错误，响应给出脱敏消息和请求标识。Java 已校验的请求若被 Python 返回 422，视为服务间契约异常，不将其误报为用户参数错误。

Java 对外 HTTP 状态沿用项目现有异常处理约定；不能只按 HTTP 200 判断业务成功。Python 的内部 HTTP 状态由 Feign 错误处理器区分处理。

## 7. 超时与故障行为

- 探测调用建议连接超时 2 秒、读取超时 3 秒；实际值可配置，未来模型接口使用独立设置。
- Feign 和 LoadBalancer 均禁止自动重试，本版本不重复发送请求。
- 未发现健康实例、连接拒绝、读取超时、内部认证失败分别记录明确错误类型。
- 停机、发现缓存尚未更新时允许调用失败，不承诺瞬时摘除实例。
- Python 恢复后，在注册和发现缓存更新后恢复调用，正常情况下无需重启 Java。
- Nacos 中断时，缓存实例可能仍可被调用；不把注册中心中断一律等同于 AI HTTP 接口中断。
- 本地故障验收要求单次失败请求在 10 秒内返回，测试覆盖无实例、连接拒绝和响应延迟；不以连接/读取超时之和冒充所有网络环境下的严格总时限。
- 本版本只有一个 Python 实例，不承诺高可用，也不宣称已完成模型限流和熔断。

本地验收时限如下。测试每秒采样一次，记录起止时间及连续三次调用成功的证据；超出时限判失败，不能无限等待。它们是本项目的目标，需经第 10 节的兼容性验证，不是 SDK 的既有保证。

| 场景 | 计时起点 | 最大验收窗口 |
|---|---|---|
| 注册中心故障状态可见 | 故障注入完成 | 30 秒内 `registry` 变为 `disconnected` 或 `unknown`；业务正常时 ready 仍为 200 |
| 异常退出实例失效 | Python 进程终止确认 | 60 秒内 Nacos 实例不再健康可选或已移除 |
| Python 重启后调用恢复 | Python 首次注册成功且 HTTP 开始监听 | 60 秒内 Java 连续三次调用成功 |
| Nacos 重启后恢复 | Nacos 自身 readiness 恢复为成功 | 60 秒内重新注册、Java 发现恢复且连续三次调用成功 |

记录所选 SDK 的心跳/保活、服务端失效、重连退避、Java 发现与 LoadBalancer 缓存参数。若受 SDK 限制无法达到上述目标，在继续完整接入前提交实测结果并修订 spec，不静默放宽验收时限。已有缓存时是否继续命中实例须如实记录；缓存丢失导致无实例时允许 Java 返回可控错误。

## 8. 配置、日志与依赖

共享配置项：Nacos 地址、namespace、group、AI 服务名、内部服务凭证。

Python 配置项：监听地址/端口、注册 IP、日志级别。Java 配置项：`ai.service.enabled`（环境变量 `AI_SERVICE_ENABLED`，默认 `false`）、Feign 超时。

- 凭证通过环境变量或 gitignored 私有配置提供；提交 `.env.example` 只列变量名称与占位值。
- 本地 Python 默认仅监听回环地址，公共访问统一经 Java 后端。
- 默认不开启内部服务的公开 Swagger 文档；开发文档可通过配置开启。
- 日志记录请求标识、服务名、耗时、状态与错误类型，不输出凭证、Cookie 或完整请求正文。
- `ai.service.enabled` 是启动期配置，改变后须重启 Java。关闭时不创建 AI Feign 客户端，不执行新增服务注册和发现；现有 Nacos 配置中心继续工作。管理员验证入口仍保留，先鉴权，合法请求返回 50001、`data=null`、消息“AI 服务接入未启用”，不调用 Python，不要求配置内部凭证。
- 开启时校验服务凭证及注册发现配置，缺失凭证使 Java 启动失败；SDK 自动配置、`@EnableFeignClients` 扫描和 LoadBalancer 配置须纳入开关控制，不能只在业务方法中判断开关。
- 新增依赖前检查旧 Nacos starter 与 Spring Cloud starter 的重复 Bean、客户端版本和配置监听兼容性。
- Python 运行依赖按验证版本锁定。首版无需安装 LangGraph、向量库及问镜的全量依赖。

### 8.1 停用与版本回退

- 功能停用：关闭开关并重启 Java，再停止 Python；验证登录、题库和配置监听。停用只禁用新功能，不撤销依赖变化。
- 版本回退：实施前记录基线 commit；如有未提交改动，额外保存完整差异与必要文件。保留基线后端 JAR、依赖树及配置模板，私有配置仍保存在忽略目录。依赖冲突或旧功能回归失败时，恢复基线构建产物与匹配配置并重启，再验证原服务。
- Git 记录必须能够还原构建依赖；不得以关闭开关宣称解决 classpath、BOM 或客户端版本冲突。回退不重置数据库、不覆盖用户后来修改的私有配置。

| 编号 | 场景 | 必须观察到的结果 |
|---|---|---|
