## 启动方法

先启动 Docker Desktop，在项目根目录启动中间件，然后在独立终端运行：

```powershell
docker compose -f compose.yaml -f compose.local-runtime.yaml up -d redis nacos sentinel elasticsearch

# 分别在 cmd 中启动本机 etcd、HotKey worker（不是客户端 JAR）和 dashboard
cmd /d /c scripts\start-etcd.cmd
cmd /d /c scripts\start-hotkey-worker.cmd
cmd /d /c scripts\start-hotkey-dashboard.cmd

# 初次或源码、配置变更后使用 -Build
.\scripts\start-backend.ps1 -Build

.\scripts\start-frontend.ps1
```

前端启动脚本默认使用开发模式，支持热更新，监听 127.0.0.1:3000。需要生产模式时使用 `.\scripts\start-frontend.ps1 -Production -Build`，构建后复制静态资源并启动 standalone 服务；已有生产构建时可省略 `-Build`。`-Dev` 仍可显式指定开发模式。切换模式前先停止已有前端服务，避免端口冲突及共用 .next 目录。

脚本中的 Java、Maven、Redis 默认路径来自本机，可以通过参数指定其他安装位置。脚本在前台运行，关闭对应终端会停止该服务。已有本次启动实例时不要重复启动，否则端口冲突。

`start-backend.ps1` 默认开启 Nacos 配置预加载和动态黑名单监听。先启动 Docker 中的 Nacos、Sentinel，再启动后端。需要临时不连接 Nacos 时使用 `-DisableNacos`，会同时关闭预加载与黑名单监听。

Sentinel 日志指定到项目 `.runtime/sentinel`，避免默认写入用户目录时的权限问题。规则文件仍按原实现写到后端目录的 `sentinel` 子目录。

后端已切换 Docker Redis 7.2.15（6380，AOF 和独立数据卷）。原 6379 实例未停止，切换前检查 127.0.0.1:6379 的 database=1 为空，因此没有迁移 Redis 数据。start-redis.ps1 是旧本机启动脚本，当前启动流程不再使用。

## 仍缺少或未启用的配置

### 按现有前端实际调用核对

当前前端需要的基础依赖为 MySQL、Redis 和后端地址，均已配置并运行。现有页面中仍缺外部凭据的功能只有 AI：管理员的 `/admin/question/ai` 生成题目页面，以及 `/mockInterview/add` 和 `/mockInterview/chat/[mockInterviewId]` 模拟面试页面，均需要有效 Ark API Key 和可用模型。

注册登录、资料编辑、题库/题目查看、后台管理、题目批量操作不需要新增外部配置；签到与日历使用 Redis。手机号和邮箱字段只是资料字段，不代表接入短信或邮件服务。Markdown 编辑器不依赖 AI 或 COS。

前端没有调用 COS 上传、微信登录、公众号、帖子点赞/收藏接口。不能因为 `src/api` 有生成的函数就认为页面已经接入。ES、HotKey、Nacos 属于可选的后端搜索/性能/安全能力；现有前端基本使用不需要先部署这些服务。
