# 面试蛙 AI 模拟面试：前后端重建与验收

日期：2026-10-12

## 页面与按钮

原 `/mockInterview/add` 和 `/mockInterview/chat/[mockInterviewId]` 整体重建，菜单仍只有一个“AI 模拟面试”入口。参考问镜的设置、面试房间、上一题反馈、报告和回放体验，保留面试蛙 Logo、全局布局及 Ant Design 主题。

| 页面或操作 | 实际行为 |
| --- | --- |
| 选择方向 | 读取现有题库，填写岗位和经验阶段 |
| 调整练习 | 难度、主问题数量、是否追问；可粘贴个人经历和岗位描述 |
| 确认开始 | 展示摘要，创建持久化会话并进入答题房间 |
| 提交回答 | 命令快速受理，后台调用真实模型评价，轮询反馈和下一题 |
| 动态追问 | 根据模型指出的缺口，每道主问题最多追问一次 |
| 跳过本题 | 确认后推进，不生成虚构评分 |
| 结束面试 | 汇总已完成评价，未答题不评分 |
| 刷新与草稿 | 服务端恢复当前题；当前浏览器按用户、会话、题目保存草稿 |
| 重试失败步骤 | 依据持久化检查点恢复；错误可见，不自动反复请求模型 |
| 面试记录 | 查看当前用户最近 30 场新面试，继续待答会话或查看报告 |
| 报告与回放 | 分项评分、优点、改进建议、逐字引用、原回答及逐题回放 |
| 复制报告 / 再练一场 | 复制可读文本，或返回新的面试设置 |
| 登录后继续 | 返回原面试或题目，只允许本站返回路径 |

旧页面和旧聊天样式不再使用。旧数据没有迁移或删除；旧创建/聊天接口明确停用，旧记录查询增加本人/管理员权限校验，不把旧 messages JSON 当作新检查点恢复。

## 主要改动与原因

- 前端新增 `src/api/aiInterviewController.ts`、`src/components/Interview/`：明确的新接口类型与反馈、报告组件，替换两张旧页面。
- Java 新增 `AiInterviewController`、`AiInterviewClient`：沿用登录态，经 Nacos/OpenFeign 调用 Python。ownerId 始终由 Java 取得，题目和参考答案从原题库构造，浏览器不能覆盖。
- `AiDiscoveryConfiguration` 注册新客户端；`AiRequestIdFilter` 将新接口纳入请求关联标识。
- `MockInterviewController` 停用旧创建与事件调用，旧详情仅允许本人或管理员查询；没有改用户现有面试数据。
- Python 新增 `app/interview/`：LangGraph 节点、固定输出契约、MySQL 命令和状态持久化、快速受理与后台执行。
- `ModelGateway.chat` 支持服务端多角色提示词，原管理员单次问答仍调用原 `complete` 方法。
- 更新运行/开发依赖的哈希锁文件，合入已验证的 LangGraph 和 MySQL Saver。
- 原登录页曾忽略 redirect；增加安全的本站返回解析，并修正登录 API 的响应类型以匹配现有解包拦截器。

## 存储与执行约束

本机新增独立 `mianshiwa_ai_interview` MySQL 库和仅限该库的本机账号。真实凭证继续放在 Git 忽略的 `.runtime/ai-service.env`，没有写入源码、文档或前端。没有新增 PostgreSQL、pgvector、Chroma，也没有修改原业务数据库账号。

每次操作包含稳定 commandId，回答另带版本和题目 ID；重复请求返回原状态，不重复推进。评价保存原回答，引用必须能在原文定位。模型输出格式或引用校验失败会显式进入失败状态。参考答案和内部模型凭证不出现在待答题响应中。

执行器当前仅支持单实例；启动前取得独立库的 MySQL 命名锁，第二个执行器明确拒绝启动，不宣称多实例接管已实现。独占连接丢失时执行器停止写入并变为未就绪，需要重启。运行中断会标记未知结果，用户明确重试；外部调用已经发生但结果尚未持久化的窗口可能产生额外费用，不承诺外部调用 exactly-once。

## 验收证据

1. Python 基础和契约测试：53 项通过；真实 MySQL/ES 集成：7 项通过，包含重复执行器启动拒绝。
2. Java 面试身份/响应契约及原探测/模型契约测试：9 项通过。
3. 本次新增和改动前端的定向 TypeScript 检查、lint 通过。未将项目原有全部类型问题作为本次已修复内容。
4. 真实 Java → Nacos/OpenFeign → Python → LangGraph → MySQL → DeepSeek：一道主问题、一次追问、两次评价、报告和历史查询通过；重复创建、重复回答、跳过及提前结束通过。
5. 浏览器实际点击：三步设置、开始、提交、刷新恢复草稿、上一题反馈、跳过、结束、报告复制、逐题回放、再练一场和历史查看通过。
6. 仅对普通测试账号模拟“图已完成但命令结果未确认”的失败窗口，点击重试恢复原报告，未增加轮次；另有真实 MySQL 的模型失败重试和首个检查点前中断恢复测试。
7. 登录后返回原面试已通过浏览器验收，7 项纯函数检查覆盖本站返回、外站拒绝及登录循环；未建立临时管理员账号。

一份完整技术回答在本次模型验收中得到 96 分，并保存原文证据和改进项；弱回答与追问的报告为 20 分。这只证明调用、展示和记录闭环，不代表已通过人工评分准确性评测。

浏览器截图保存在本机 `.runtime/interview-setup.png`、`interview-room.png`、`interview-report.png`，包含合成测试回答，没有真实个人经历。验收使用普通临时测试账号，测试账号及所属面试记录在结束前清理，用户现有账号和记录不受影响。

## 尚未包含

首版评价依据是冻结的题目参考答案及固定的三维评价定义，尚未完成逐题人工审核的结构化评分合同。选题仍按所选题库的稳定编号顺序执行；难度、岗位和背景用于评价及追问上下文，不冒充题库已拥有难度筛选元数据。

ES BM25/向量路径已在阶段 0 验证，但本次面试未接入真实 Embedding、混合检索智能选题或 Agentic RAG。简历文件上传、语音视频、长期能力档案、多步检索和策略学习均未添加伪功能按钮。
